## 数据与冻结设计

从已有只读来源权威重开 `510300.SH` 的 `fund_daily/fund_adj`，发现 2014-01-02 至 2024-12-31 共 **2,676 个交易日**的 OHLCV 与复权因子。无新增行情请求，未复制凭据至 DL。它们是当前收件的已打开历史版本，属于 Modeled-PIT；本次计算检查不能证明历史版本在当时已可获得。一个预选且存续的 ETF 也不能代替历史股票池、退市处理或横截面选股验证。

[冻结协议](research/dl-first-round-20260908/protocol.md)先于拟合记录：原三个开发窗口仍为 2015 年 52 日、2018 年 120 日、2024 年 6 日；最后 60 个测试前特征日作为验证，其前扩展训练。训练标签跨入验证、验证标签未在首个测试开盘前到期时剔除。预处理只拟合训练侧，验证/测试均未用于选参数。三个窗口可评分的到期 H5 标签分别只有 **48、116、2** 个，且 H5 重叠，不能当作独立样本。

原生 Qlib 0.9.7 计算全部 Alpha158；另以原来的 ROC/MA/STD 5/20/60 九特征做消融。Ridge 与 LightGBM 使用维护库的公开估计器，不引入 Qlib 的账户或执行栈，也不声称复现其官方横截面 benchmark。逐日价格乘当日复权因子，成交仍使用原始价；成交量与成交额单位经 VWAP 位于 OHLC 区间的检查，复权/分红预测标签仍与原生账户收益分开解释。

## 数值预测

每特征组固定 Ridge(alpha=1) 和小型 LightGBM（100 树、7 叶、学习率 .05、seed 17、16 线程），共 12 个独立配置。没有因子搜索、阈值优化或事后剪裁预测。下表为 H5 收益预测 MSE，越低越好；零收益也是必须保留的预测对照，不能与现金账户收益混用。

|---|---:|---:|---:|
| Alpha158 / Ridge | 0.212980 | 0.001809 | 0.077318 |
| Alpha158 / LightGBM | 0.010858 | 0.001474 | 0.073959 |

## GPU 与模型可行性

已复核 RTX 5090、32,607 MiB、驱动 595.84；PyTorch 2.13.0+cu130 在 SM 12.0 上实际张量计算通过。独立 vLLM 0.28.0 / Transformers 5.16.1，未修改系统驱动、Python 默认版本或上游源码。[完整依赖](research/dl-first-round-20260908/vllm-requirements.lock)可重建实验环境。

候选为 [官方 Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B)，revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a`、Apache-2.0，BF16 权重约 19.31 GB。16 个文件均与独立取得的原站元数据核对大小及哈希。[完整性回执](research/dl-first-round-20260908/model-integrity.json)。只用文本、单并发、16K 总上下文上限、eager 模式；模型结果不构成 pi Provider 准入。

部署过程保留三次启动失败：实验脚本缺少多进程 main 保护；FlashInfer 未发现 nvcc；配置隔离环境内 nvcc 后遇到 CUDA 头文件不兼容。后两项与上游 [nvcc 发现问题](https://github.com/vllm-project/vllm/issues/49497)及 [Blackwell JIT 问题](https://github.com/vllm-project/vllm/issues/44305)相符。最终通过公开配置 `VLLM_USE_FLASHINFER_SAMPLER=0` 使用 vLLM 自带采样器，无源码补丁或系统 CUDA 安装。原站连接超时与镜像 Xet 401 也保留；关闭 Xet 后 HTTP 下载成功，未发送 HF token。

### 固定合成抽取测试

12 个提前冻结的中文例子，覆盖增长/下降、预告、缺失、更正、矛盾、未来资料、正文指令、单位换算、零基数、区间与错公司/期间。机械规则基线为 **11/12**，未处理单位换算；这些简单题并不是现实公告或投资研究的充分代表。

最初为固定贪心解码：非思考 24/24 返回 JSON，22/24 完全匹配，12 对重复文本与解析结果相同；两次均误用未来更正。思考运行收到 7 个输出，其中 4 个耗尽 2,048 tokens，随后显式停止：原计划 48 请求中，31 个有输出、1 个在途取消、16 个未启动。未把它改标为完成，也未补造取消请求的 token 用量。[原试验回执](research/dl-first-round-20260908/gpu-greedy-summary.json)。

随后完整执行官方通用任务采样参数的 24 个请求，每模式 12 题、一个种子；案例与 2K 输出上限不变。思考/非思考温度分别 1.0/.7，top_p .95/.8，均 top_k 20、presence_penalty 1.5。模型卡通常建议更长输出，因此这检验的是**限定成本的抽取可行性**，不是模型的无约束能力排名。

| 官方采样、每模式 12 题 | 非思考 | 思考 |
|---|---:|---:|
| 直接返回可解析 JSON | 12/12 | 2/12 |
| 原始严格字段/出处完全匹配 | 9/12 | 2/12 |
| 次级诊断：仅去掉完整代码块外壳后，核心数值与状态正确 | 11/12 | 4/12 |
| 耗尽 2K 输出预算 | 0/12 | 8/12 |
| 请求耗时中位数 | 1.16 秒 | 70.89 秒 |
| 输出 tokens 合计 | 376 | 19,258 |

思考另有两题在完整 JSON 外加代码块，内容正确；不能把这两题算作事实错误。非思考的两项额外出处选择差异与一个真实未来来源错误分别保留。次级格式诊断不改写原始答案、严格成绩或生产解析器。[完整模型结果](research/dl-first-round-20260908/gpu-recommended-summary.json)、[格式/语义分解](research/dl-first-round-20260908/extraction-secondary-audit.json)。

本轮不足以决定默认思考模式或模型大小：2K 上限造成大量截断，且尚未实测其他候选。对未来来源问题，先由确定性时间过滤删除不合格记录，同一非思考案例随后 **2/2 正确**；原来的错误保留。这支持 Harness 必须先控制来源资格，不支持把 PIT 权威交给模型。[截止时间职责诊断](research/dl-first-round-20260908/cutoff-owner-diagnostic.json)。

### 容量、成本与退出状态

四个额外非思考容量案例均正确：3,999 与 13,999 输入 tokens，各把相关事实放在开头/结尾；对应短输出 30–32 tokens。暖运行耗时约 1.43–1.46 秒与 1.98 秒。prefix cache 开启、填充文本高度重复，因此不是独立长文吞吐或复杂理解基准，也未测 14K 输入加满 2K 输出的极限峰值。[容量回执](research/dl-first-round-20260908/long-context-results.json)。

0.5 秒目标间隔采样的显存最大值为 **28,514 MiB（约 27.85 GiB）**；短请求为 26,888 MiB。首次贪心短请求含额外 JIT，耗时 116.54 秒，不能用暖运行中位数掩盖冷启动。后继官方采样运行加载约 36.59 秒，总计 722.81 秒。vLLM 主进程最大 RSS 约 1.60 GiB，未取得完整工作进程族的全程主机内存峰值，不能把它当成总 RAM 用量。

累计发起 62 次本地生成请求，61 次收到输出、1 次在途取消；长度终止属于收到输出但抽取未完成。配置不同的试验不合并成一个成功率。新增付费 API 调用及费用为零，设备电费未计价。模型与依赖缓存保留；退出后 GPU 18 MiB、利用率 0%，磁盘约 192 GiB 可用，无模型服务监听或遗留实验进程。[资源回执](research/dl-first-round-20260908/resources.json)。

27B GGUF Q5 未下载，本轮没有发现必须用更大模型解决的具体需求；QUASAR NVFP4 原 revision 未变，当前元数据仍缺少许可字段与独立 LICENSE，亦未下载或声称本机可运行。未来只有在更贴近真实任务的质量差距成立时再做单独对照，不能因模型卡宣传自动采用。

## 2026-09-08 用户复核后的结论修正

首轮结果保留不变；以下修正结论的适用范围，不代表已完成新一轮实测。

- **选型尚未完成。** Qwen3.5-9B 仅是已测基线。重新核验官方 Hub/API，当前 Qwen3.8 发布列表未见官方 9B；不能用社区名称冒充官方更新。近体量应补 Gemma 4 E4B IT（含 embeddings 共 8B），略放宽参数量则优先对照 Gemma 4 12B IT。Google 的 [12B 公告](https://blog.google/innovation-and-ai/technology/developers-tools/introducing-gemma-4-12B/)发布于 2026-06-03，比 Qwen3.5 小模型更新；模型仓库创建时间不是发布日期。既有候选 Qwen3.8-27B 的量化版本可作为同一 32GB 设备预算下的能力对照，但不是同参数量。以上模型是否更适合中文财务抽取与证据分析均需任务实测，不能由通用榜单判定。
- **2K 思考测试存在预算限制。** [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B#best-practices)建议多数查询最大输出 32,768 tokens；本轮 2,048 包含思考与最终答案。8/12 长度终止说明该配置预算不足，不能判为模型能力失败，也不能据此淘汰思考模式。补测应将短答案的非思考路径与 8K/16K/32K 思考预算分开报告，比较完整答案质量、截断率、实际 token 和延迟；32K 输出须先扩大原 16K 总上下文配置并验证显存，不能只改 max_tokens。
- **停止理由应分流。** 单 ETF、少量且已打开的开发窗口，足以支持暂缓原数值配置盲目扩搜，不能证明所有学习方法无效，更不能否决文档模型。LoRA 缺代表性监督数据和独立确认集，交易 RL 缺可信多状态环境及奖励/成本验证，暂缓合理；补齐推理预算、真实任务样本和有限候选对照则有直接的信息价值。原笼统的“不继续更多大模型下载”结论撤回。

本次仅核验来源与修正文档，未新增 GPU 实验；原 12 题与相关正确率仍仅是合成抽取结果。后续评测需覆盖真实中文公告的数值/单位/期间、版本更正、跨文档矛盾、出处可追溯和拒答，并把抽取质量与投资收益分开验收。
