## 已完成：两轮本地账户组合及撤销修复

新增组合验收沿用原有调度复核入口、组合权威、自主执行服务和 Mock 账户：
第一次定时复核建议买入，提交只产生 ACK；后续实际收件的合成行情触发模拟

第二次定时复核收到成交后的完整账户，建议保持持仓。合成行情和模型响应仅
替代外部输入，内部准入、费用、成交、对账和持久化均走真实组件。

首次组合验收发现：已撤销租约的执行入口重开时，先调用一次 Mock 对账，再
拒绝租约。该调用读取回执，未观察到由此产生下单或成交写入。修复将已有租约
验证与对账调用放在同一权威事务内，阻止先调用后拒绝，并与并发撤销串行化。

中断恢复保留原有权威：存在未结束提交时，入口先不读取 Provider 或投影账户，
由原执行服务恢复为 UNKNOWN，绝不重新提交。只有随后重新验证授权的显式
对账能够恢复账户；若期间请求撤销，恢复先完成撤销，对账不再调用 Provider。
撤销不是取消已被市场接受的订单，既有订单的模拟成交事实与新提交权限分开。

这项验收包括两次原生 pi 子进程调用，响应由本地传输替身提供；没有真实模型
请求、券商调用或后台调度服务启动。新闻修复与这项生命周期修复均经独立
只读评审，无剩余具体问题。完整仓库 Ruff、格式和 Pyright 检查通过；包含下述解析修复的最终 pytest 为 2,228 passed、212 条弃用警告。
