# Expanded numerical research and conditional news increment

Core development design frozen before fitting the expanded Tushare data, 2026-09-08. The conditional fresh-confirmation section was added after initial fold-A development results, before nomination or any 2025–2026 model outcomes; its timing is disclosed separately below. This supplements the original round-two protocol after the user's explicit authorization to expand the universe, history and GPU research, and to prioritize model effectiveness as a possible main capability.

## Priority and claims

First establish a useful numerical model using only market data. Compare maintained supervised and formula-search implementations. A modern or larger RL network is a candidate, not a required winner. Select the strongest supported candidate among those actually tested, never call it globally the most effective model. The existing three-model document experiment remains a separate extraction assessment and does not establish investment value.

Only after the numerical model passes development gates should a frozen small language model add structured news/event features to an otherwise identical pipeline. Compare market-only against market-plus-news; a shuffled or delayed news control must help distinguish added information from capacity or calendar effects. Event categories, affected instruments, signed surprise, uncertainty and effect horizon are possible inputs. Publisher time, actual availability, revisions, entity mapping and deduplication remain explicit. Do not use current model knowledge of historical outcomes as observed news evidence. If historical availability cannot be established, use prospective paired collection for that increment.

## Data scope and ownership

Private Tushare capture target: 2010-01-01 through 2026-09-07, all daily A-share rows, including historical delisted instruments. Capture raw daily OHLCV/amount, adjustment factors, daily limits and daily basic indicators, plus trading calendar and L/D/P listings. Daily-by-date acquisition follows the provider's recommendation. A 5,000-row page is below the documented daily/limit caps; compare each expanded route against the existing 1,000-row configuration on the newest complete date before bulk use. Preserve bounded pagination, exact private response bytes, hashes, actual receipt and deterministic capture replay using the existing Provider. This research cache does not automatically qualify the new configuration for Agent tools or promote retrospective observations to historical PIT evidence. Current listing metadata must not define historical membership.

Use a maximum 3.33 requests/second across eight I/O workers, bounded retries for transport failures, and resumable per-date captures. Do not replace failed/empty partitions with invented values. Audit gaps, duplicate keys, row counts, symbol history, price/volume units, adjustment coverage and limit coverage before fitting. Amount is CNY thousands and volume is lots of 100 shares; derived daily VWAP is amount * 10 / volume where volume is positive. Preserve raw executable prices separately from adjusted research inputs. Flag the lack of provider revision history and treatment of delisting returns.

## Structured feature increments

The user additionally authorized testing daily valuation/size/turnover indicators before news. Fix three feature tiers: (A) price/volume/amount and derived features; (B) A plus daily PE/PE-TTM, PB, PS, dividend yields, turnover, free-float and market capitalization from the captured daily_basic route; (C) B plus financial statement indicators only where disclosure availability and revisions can be handled correctly. Keep the model budget, temporal folds and portfolio constraints matched. Do not imply that extra fields must improve results. Negative/missing valuation ratios remain typed missing with training-fitted handling; do not treat them as cheap valuation or retrospectively fill them with future values. Current-vintage daily indicators are retrospective research inputs unless their historical vintage is established. Financial report period-end is never its availability date. Before any expanded fitting, the user requested an initial-version default and the official Tushare FAQ confirmed update_flag=0 means initial and 1 revised. The financial tier therefore uses unique initial-version records, collapses identical initial duplicates, excludes conflicts between initial records and keys with no initial record, and becomes effective on the next exchange session after ann_date. The earlier conservative derived table is retained for audit; raw captures are unchanged. This defines an initial-disclosure baseline, not a complete dynamic revision timeline.

## Temporal evaluation

Development fold A: train 2010–2018, validation 2019–2020, test 2021–2022. Development fold B: train 2010–2020, validation 2021–2022, test 2023–2024. The folds are sequential development studies, not independent confirmations. Purge training and validation labels crossing their next boundary; fit processors and universe liquidity filters only with information available on their own side. All 2025–2026 outcomes remain unopened until the selected model, configuration and success criteria are recorded. Seeing capture row counts/schema is not reading model performance.

Use three predeclared random seeds (17, 29, 43) for stochastic candidates. Begin with one seed per development fold to verify complete data and compute paths; expand the same fixed design after those functional checks. At least a linear and LightGBM supervised baseline must accompany formula/RL search. Compare LSTM and the upstream Transformer only with explicitly matched search resources; record actions, attempted/valid/unique formulas, optimizer updates, wall time and peak memory. Equal action counts alone do not mean equal valid-candidate budgets. Use an additional random search control matched to the learned search's completed valid candidate count. Select budgets from training-only throughput measurements before outcomes are inspected.

RankIC by year/date block is a signal diagnostic. Investment claims additionally require the existing account/execution constraints, next-session availability, turnover, transaction costs, doubled-cost sensitivity, exposure-matched reference and delisting/suspension handling. An upstream research simulator result is labelled as such. No production execution integration is authorized by positive research metrics alone.

## Hardware and method selection

CPU handles acquisition, feature preparation and CPU-efficient baselines. GPU handles eligible tensor/factor calculations and policy training; measure identical bounded training workloads on CPU and GPU before choosing the split. Parameter count and GPU residency are not evidence of acceleration or generalization. Maintain pinned upstream code and record caller adapters, dependency differences and failures. Newer methods are screened for available code, reproducible objectives, train/test separation and practical single-5090 execution before actual use.

## Concrete pre-fit implementation choices

The expanded supervised and formula-search comparison uses the same five-session forward target, `Ref($close,-6)/Ref($close,-1)-1`: features after session t close, return from t+1 close to t+6 close. Six trailing feature sessions are purged at training/validation and each development test boundary. The first 100 exchange sessions provide feature warmup. An eligible symbol has at least 60 observed sessions, trailing 60-observation median amount at least CNY 10 million, raw close at least CNY 1, positive volume and a valid adjustment factor. Selection uses no current-survivor list.

The supervised tiers use pinned Qlib Alpha158 and the same training-fitted robust scaling/clipping and missing-value fill. Ridge uses the maintained Qlib LinearModel with alpha=1 and intercept. LightGBM retains the previously pinned published Alpha158 configuration (including learning rate, regularization, depth and leaves), changing only thread count to 16 and the registered seed. Five positive-ratio inverse valuation features, turnover/volume ratios, dividend yields and log size/share measures define tier B. Tier C adds the initial-disclosure financial indicators and their availability age; an observation older than 540 days is not carried further. These are pre-fit defaults, not choices based on observed development scores.

## Predeclared development nomination gate

Before expanded development outcomes are opened, a numerical candidate must have positive mean daily RankIC in both development tests and positive annual RankIC in at least three of the four test years (2021–2024). For stochastic candidates, at least two of three seeds must pass the positive-mean condition in each fold; average seeds by date before uncertainty calculation so seeds are not treated as independent market observations. Use 60-session moving-block resampling within each fold, 2,000 draws with seed 17029, for the combined equal-fold-weight mean and paired differences. Require the candidate's combined mean lower 95% percentile bound above zero to nominate it for fresh confirmation. Rank passing candidates by their lower of the two fold mean RankICs; ties within 0.001 prefer fewer feature tiers, then the simpler model. Additional-feature claims require a positive paired difference against the same model's immediately smaller tier; report its uncertainty even when the difference is not established.

This gate nominates a predictive research candidate. Account returns after base and doubled costs, turnover and drawdown are separate required diagnostics. CSI300 is a contextual benchmark with different size exposures from the expanded universe; beating it alone does not establish stock-selection alpha. Missing delisting proceeds and unaccepted native execution rules remain barriers to an investment-capability claim. Do not add news or open 2025–2026 model outcomes merely because one development chart looks favorable. Record the chosen candidate and unchanged configuration first; if no candidate passes, report that result without searching the holdout for a rescue.

A learned formula-search candidate also needs a positive paired RankIC difference against its matched random-search control with the combined lower 95% bound above zero before attributing value to learning. If added feature tiers have an inconclusive paired increment, present them as unresolved and prefer the smaller tier for confirmation unless it fails the base nomination gate; do not call an uncertain difference an established improvement.

## Training-only adapter correction and compute validation

The first expanded throughput profiles exposed a caller-adapter defect before any formal development fitting: restoring every expression's own missing-value mask produced pairwise-deletion correlations on different asset samples. The MSE pool assumes a valid joint correlation geometry. Reconstructing the completed training-only LSTM pool gave a minimum eigenvalue of -0.8632 and weights up to 72.59 in absolute value. These throughput profiles are invalid for model-effectiveness evidence and their unfinished siblings were stopped; logs and derived artifacts remain available privately. This is an adapter defect, not evidence against the upstream learning method.

The corrected adapter excludes historically ineligible assets, retains upstream zero imputation for missing normalized expressions within the eligible universe, and uses one observed-label population for all training-objective correlations (including mutual correlations). Prediction normalization never uses the future-label mask. Re-evaluating the same 20 expressions gave minimum mutual/joint eigenvalues within 9e-15 of zero. No clipping, regularization change or outcome-driven formula filtering was introduced. All expanded formal searches will restart under this corrected, recorded adapter.

An optional per-calculator LRU cache retains at most 64 immutable normalized expression tensors; it is scoped to one immutable data segment and never crosses train/validation/test calculators. Real training-data checks establish exact equality to uncached expression evaluation and show that correlation calculations do not mutate cached values or the target. The cache changes repeated computation only. MSE weight optimization uses the upstream independent `device` argument, allowing CPU weights with CUDA formula tensors and policy training; device selection is based on corrected training-only profiles.

## Frozen expanded compute budget

The [compute selection](expanded-compute-selection.json), recorded after the corrected training-only profiles and before expanded development fitting, fixes 131,072 policy actions for each LSTM/Transformer × two folds × three seeds. This is 32 times the old 4,096-action pilot budget per learned search, with a 20-factor pool. The matched random control targets the larger learned unique-admission count within each fold/seed, subject to a predeclared 2,097,152-action ceiling. A control that does not reach the target is explicitly unmatched.

Use CUDA formula calculations and policy networks, CPU pool-weight optimization, a 64-entry segment-local factor cache and four native CPU threads per GPU job, with at most two GPU jobs concurrently. Corrected 8,192-action training-prefix profiles completed in 76.6 seconds for LSTM and 134.1 seconds for Transformer, with 272 and 445 unique admission candidates respectively and roughly 3.0/2.3 GiB peak allocated CUDA memory. These are concurrent throughput observations on the training prefix, not full-data runtime promises or a pure architecture speed comparison.

The CPU sweep tested 32/64/128/192 feature processes on identical 2015 training data; all produced exactly equal frames. Use the fastest observed configuration of 128 processes with one native thread each. LightGBM's fixed 20-round training-prefix sweep tested 16/32/64/128/192 threads; 64 and 128 took about 6.0 and 5.7 seconds, while 192 took 35.1 seconds. Use 64 threads per model and up to two independently seeded/folded fits when memory permits; this supersedes the initial 16-thread placeholder. Stagger their preprocessing and retain at least 70 GiB available before admitting a second fit. Persist the fitted inference processors, then use maintained `DataHandlerLP.cast` to release the raw loader and retain processed data. A repeated complete smoke fit produced the same predictions after this memory-lifetime change.

## Size-control check before nomination

Also fixed before expanded outcomes are read: evaluate partial Spearman RankIC by correlating residualized within-date prediction/return ranks after controlling the rank of observed circulating market capitalization. Use the same captured daily field for all methods; it is an evaluation control and is not added to a price-only model's inputs. Missing size observations are excluded from this diagnostic and coverage is reported. A prediction entirely explained by size receives zero incremental RankIC rather than dropping that date. Require positive mean size-partial RankIC in each development fold and a positive combined lower 95% block-bootstrap bound for final nomination. This is a one-factor diagnostic, not a sector/beta-neutral or exposure-matched executable account claim. The formula has been checked against direct residual regression and a pure-size control on synthetic data.

Within the previously defined 0.001 tie tolerance and feature-tier preference, the simpler-method ordering is Ridge, LightGBM, random factor pool, LSTM search, Transformer search. Random search can be retained as a numerical candidate if it passes the same predictive gates, but no gain is attributed to learned search without its stronger paired-control gate.

## Conditional fresh temporal confirmation

If and only if a candidate passes the final development nomination gate, record its identity and configuration before opening 2025–2026 model results. Retrain the same selected method and feature tier with training through 2022, validation in 2023–2024 and confirmation from 2025-01-01 through the final six-session-purged 2026-09-07 boundary. Keep the same preprocessing, hyperparameters, search budget, seed policy and account rules; the training window advances by the same two-year pattern used by folds A/B. Ridge remains deterministic; stochastic candidates retain all three seeds. Do not select a better seed after seeing confirmation.

Fresh predictive confirmation requires positive raw and size-partial mean RankIC in both calendar years represented, positive combined 95% 60-session block-bootstrap lower bounds, and positive overall raw and size-partial means in at least two of three seeds for a stochastic method. A nominated learned formula search also retains its candidate-matched random control and paired-gain requirement. Report full-seed base/doubled-cost accounts separately. Failure does not trigger a new candidate choice using this holdout; record the failed confirmation. If no development candidate qualifies, leave these outcome results unopened. A passing retrospective confirmation still does not establish provider-vintage PIT or native investment/execution acceptance.

The fresh-confirmation uncertainty estimate uses equal calendar-year weights (2025 and the available 2026 sessions), 2,000 within-year 60-session moving-block draws with seed 17029, after averaging stochastic seeds by date. This clarifies the combined estimate before nomination and before fresh outcomes. A learned nominee uses its unchanged 131,072-action budget and a fresh random control matched to that nominee's unique admission count separately per seed, under the existing ceiling. If random search itself is nominated, its fresh per-seed valid-candidate target is frozen to the corresponding development fold-B control target before fresh fitting; it is not chosen from confirmation performance.

## Resource failure and recovery

The first full-data concurrent fold-B tier-C Ridge/LightGBM run triggered a kernel-confirmed global out-of-memory kill at 2026-09-08 13:12:23 server local time. Ridge resident memory was approximately 73.39 GiB and LightGBM 48.87 GiB. The earlier admission threshold did not cover the later simultaneous fitting peaks. The original CPU lane paused automatically. Preserve that failed attempt and its logs, then run the missing original CPU jobs serially with the same adapters, data, 64 threads, hyperparameters and seeds. GPU searches and the account lane remain with the original controller. This resource-only recovery changes no research budget or model gate.

The fresh formula adapter uses upstream `StockData.max_future_days` to reduce unused padding from 30 to the six actually available sessions at the final data edge; earlier segments retain 30. Synthetic exact-equality checks cover close, lag, rolling mean and the frozen five-session label on identical 100-date/three-stock inputs. This preserves the declared last prediction date and does not invent future sessions or change the label. The original development adapters are unchanged.

Candidate-count interpretation: `unique_admission_candidates` deduplicates expression text among candidates that increment the maintained pool's evaluation counter after its pre-admission checks. It is not a count of independent economic factors or a proof that all algebraically equivalent expressions were canonicalized. The control matches this frozen implementation-level search opportunity count; statistical uncertainty still uses market-date blocks, not candidate counts.
