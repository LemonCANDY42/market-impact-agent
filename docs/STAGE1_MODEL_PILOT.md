# Stage 1 Luna/Terra pilot

This bounded extension executes Stage 1 using the existing pi runtime and research
thesis authority. The user authorized a new USD140 ceiling on 2026-09-06. It does
not enable paper or live trading, and does not advance Stage 2 or Stage 3.

## Frozen comparison

Register two historical development windows, two evidence arms (`price_only` and
`price_and_event`), and Luna max / Terra high before dispatch. The eight Runs use
the same target, cutoff, five-session horizon, frozen evidence tool, and question;
serial ordering is counterbalanced. No acquisition successors or semantic retries
are included. Terminal failures remain in the denominator. H1 is only an auxiliary
movement diagnostic of the H5 forecast, not an independently elicited prediction.

The original preparation remains immutable. Verified CSRC publisher captures may
supplement the 2024 missing-event arm in the execution registration. Current
publisher pages establish modeled historical availability, not contemporaneous
receipt. A page-generation timestamp is excluded only when explicitly labeled and
exactly equal to that metadata timestamp; unexplained date conflicts fail closed.

Choose Luna as a development research default only if all four Runs complete,
source review finds no critical unsupported claims or material loss in evidence,
expectations and counter-scenario reasoning, and observed model cost is lower.
Historical direction hits do not determine model promotion. Two selected windows
cannot establish trading effectiveness or broad model equivalence. Portfolio and
longitudinal update usability require their own evidence.

## Authority and execution

`market-impact agent continuous-study prepare-execution --execution-config PATH` freezes the panel.
`qualify-execution --offline-verification PATH` qualifies exactly the registered
Luna/Terra routes against current offline checks and independent review.
`run-execution` dispatches; `report-execution` reopens native signed results without
new model calls. All commands use the same `--state-root` and `--panel-id`.

A durable authorization parent allocates USD1 to route qualification, USD45 to the
complete paired panel, USD34 to usability and USD60 to bounded follow-up. These
are ceilings, not spending targets. Unknown requests retain reservations and block
further dispatch. Panel revisions must retain this parent and prior spending;
complete-group allocations cannot be assumed released when actual spend is lower.
The eight-Run worst-case allocation is computed from the registered profiles.

Verification covers the production entry, evidence isolation, native replay,
terminal failures, budget ancestry and restart behavior. Private historical input
integration cases skip on clones without those captures; synthetic boundary tests
remain available. Full local Python and pi checks precede paid qualification.

## Content review rubric

Review paired outputs without model names, costs or realized outcomes first. For
each output record whether (1) claims and references match supplied documents,
(2) price and event evidence are distinguished, (3) priced expectations are
explained without invented facts, (4) the strongest counter-scenario and observable
falsifiers are useful, and (5) uncertainty and missing evidence are represented.
Use `adequate`, `minor_gap` or `material_gap` for each criterion, with concrete
citations. A fabricated material fact, post-cutoff fact or unsupported causal
certainty is critical. Compare matched-arm differences before unblinding cost and
model identity. This is a bounded qualitative development assessment, not a
statistically powered non-inferiority test.

## Input interpretation

Treat cited source statements as facts, and keep any economic transmission from
those facts to a target as a hypothesis to assess rather than evidence that the
mechanism occurred. Record missing event, publication, policy-effective, or
expectations evidence as an explicit unknown. For historical windows, a current
publisher page can establish modeled availability but not contemporaneous receipt;
`retrieved_at` records the current capture and is never backdated. Price rows retain
the actual `raw_close`; compare returns only on one consistent
`cutoff_adjusted_close` basis and never mix the two. The complete source and factor
proof remains in CAS behind the frozen input.

## Explicit qualification recovery

The first paid qualification completed Luna but rejected Terra's JSON because
`typed_unknowns` was an object; the V2 prompt had not specified that field's array
type. Both calls settled, totaling 19,223 microUSD. This is retained as an interface
failure, not evidence of inferior market reasoning. The prompt now states array
and scalar types explicitly without relaxing source or authority validation.

An explicit `qualify-execution --prior-qualification-root PATH` registers a
successor only to a failed, reconciled qualification. It preserves every prior
report, freezes the immediate predecessor and original budget group, and uses
fresh Run IDs. Each failed predecessor can have only one successor; claims in the
shared parent prevent forks. All attempts consume the original six-call / USD0.50
allowance per route. No allocation is released or renewed. Research-panel terminal
failures still have no semantic retries.

The first successor corrected the JSON shape, but Terra then exposed a domain
invariant mismatch: supported event evidence was incorrectly required to imply a
nonempty target transmission. The contract now retains supported-event citations
and explicit missing-transmission gaps while allowing an unknown target direction.
The second failure stays failed. A diagnostic parse of its stored answer may verify
the fix, but cannot manufacture a completed native terminal or qualification.

This finding also replaced the provisional one-recovery counter with the bounded
predecessor chain above. The original cumulative physical-call and dollar limits
remain the spending authority; corrections do not authorize unbounded retries or
changes aimed at obtaining a preferred market forecast.

## Completed pilot

The [2026-09-06 results](STAGE1_MODEL_PILOT_RESULTS_20260906.md) complete both windows
and all eight research Runs for $0.310599 including qualification. Luna was not
promoted because its 2020 event answer introduced an unsupported material policy
channel. The result is a bounded development finding, not trading acceptance.

The accepted [source-first follow-up](STAGE1_FOLLOWUP_20260906.md) fixes input
semantics, freezes two new 2025 windows with a momentum comparator, and records a
