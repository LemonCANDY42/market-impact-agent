# Qlib、FinRL 与 LLM/RL 研究路线评估

日期：2026-09-07。范围：官方实现、论文方法与公开工件核验，以及下一轮实验建议。没有安装框架、启动服务器训练、调用付费模型或改变交易准入。本报告是研究提案，不修改已冻结研究的样本、预算或成功标准。

后续模型资料：[最新模型候选与单卡部署判断](MODEL_SHORTLIST_20260907.md)。

## 判断

优先顺序建议为 **Qlib 监督学习基线 → 有界 LLM 因子研究 → 小型 RL 仓位策略 → LLM 强化学习训练**。前两步最容易回答当前缺口：是否存在费用后可利用的信号，以及 Agent 能否贡献额外信息。拥有多 CPU 服务器和单卡 5090，使低成本本地对照可行，但不能增加独立市场样本，也不能消除历史知识泄漏。

算法收益、Agent 增量、自动化可靠性仍需分别证明。上一篇[投资能力评估](INVESTMENT_CAPABILITY_ASSESSMENT_20260906.md)只复现了 Qlib 的九个 close-only 特征，没有训练 Alpha158 模型；30 条 SMA 账户路径也未出现一致收益风险改善。这些是本项目已完成的有限证据。本次新增论文结果均为作者报告，尚未在本项目复现。

## 候选优先级与证据

| 路线 | 当前证据与限制 | 建议职责 |
|---|---|---|
| **Qlib：Alpha158 + 线性模型/LightGBM** | 官方提供因子、训练、评估与模型基准；已具备项目内部分原生特征复现基础。框架完整不等于模型有效。[官方仓库](https://github.com/microsoft/qlib) | 第一优先。隔离研究特征/分数，建立可部署学习基线；不搬入其账户与执行栈 |
| **Qlib：滚动训练、动态适应** | 官方有动态基准与滚动研究实现；历史榜单不能外推至当前行情。[动态基准](https://github.com/microsoft/qlib/blob/main/examples/benchmarks_dynamic/README.md) | 先比较固定模型与普通滚动重训。只有出现稳定漂移损失才测试更复杂适应方法 |
| **RD-Agent-Quant** | 有完整上游工程和因子/模型联合研究论文；比只有概念或权重卡的项目更适合复用。[代码](https://github.com/microsoft/RD-Agent)、[论文](https://arxiv.org/abs/2505.15155) | 第二优先。先用固定 LightGBM，只研究少量新因子，暂不同时搜索模型与因子 |
| **AlphaBench** | ICLR 2026 的生成、评价、搜索基准，官方指出生成能力与判断有效性的能力不同；已有代码。[论文](https://proceedings.iclr.cc/paper_files/paper/2026/hash/4f3820576130a8f796ddbf204c841487-Abstract-Conference.html)、[代码](https://github.com/CityU-MLO/AlphaBench) | 优先借鉴测量方法：可执行率、去重、样本外 IC、搜索成本。仅复用需要的模块，不引入新服务/引擎 |
| **AlphaGen / HARLA** | AlphaGen 是 KDD 2023 的 RL 公式组合搜索；同一官方仓库已包含 LLM 辅助扩展并引用 2026 HARLA 论文。[代码](https://github.com/ICT-FinD-Lab/alphagen)、[原论文](https://doi.org/10.1145/3580305.3599831) | 比直接训练 LLM 下单更值得先测的 RL 方向。作为固定搜索预算下的对照，检查新增因子对已有组合的贡献 |
| **FinRL / FinRL-Meta；SB3 或 ElegantRL 算法** | FinRL 当前官方定位保留教育/研究版本；上次项目源码核验已发现自带 China 环境与本项目 T+1/可卖库存等语义不同。[官方定位](https://github.com/AI4Finance-Foundation/FinRL)、[Meta 论文](https://arxiv.org/abs/2211.03107) | 第三优先。选择一个维护中的算法实现，先测 PPO 的小动作空间仓位策略；环境须使用项目认可的账户状态转移 |
| **FinRL-X / FinRL-Trading** | 官方后续框架，强调选股、配置、择时、风险与权重接口一致性；属于整套交易基础设施。[论文](https://arxiv.org/abs/2603.21330)、[代码](https://github.com/AI4Finance-Foundation/FinRL-Trading) | 借鉴组合接口与模块分工。当前没有迁移整套框架的必要，也不能把论文架构主张解释为本项目收益证明 |
| **FinRL-DeepSeek** | 冻结 LLM 为新闻生成情绪/风险分数，再影响 PPO/CPPO；不是通过 RL 训练 LLM。论文结果混合，详见下文。[论文](https://arxiv.org/abs/2502.07393)、[代码](https://github.com/AI4Finance-Foundation/FinRL_DeepSeek) | 作为“新闻特征是否有增量”的实验设计参考，不直接采用作者 actor |
| **Alpha-R1** | 8B LLM 经 RL 做因子启停筛选。官方仓库当前仅 README，推理代码和权重仍列为待发布。[论文](https://arxiv.org/abs/2512.23515)、[仓库](https://github.com/FinStep-AI/Alpha-R1) | 方法值得借鉴，完整复现暂缓。搜索发现的同名第三方模型卡不自动视作作者发布工件 |
| **Trade-R1 / Trading-R1** | 两篇不同工作：前者研究过程一致性奖励；后者研究交易推理训练。短窗口及工件/资源限制见下文。[Trade-R1](https://arxiv.org/abs/2601.03948)、[Trading-R1](https://arxiv.org/abs/2509.11420) | 先借鉴事实—推理—决策一致性评价。LLM 训练排最后，不能因理由更忠实便声称收益提高 |

另一个有明确后续论文的观察候选是 [AlphaQCM（ICML 2025）](https://proceedings.mlr.press/v267/zhu25ag.html)，研究价值分布估计用于公式因子发现。本轮仅核验论文入口与方向，未完成源码/实验审计，因此不将其排在已经可直接建立对照的路线前面。

## 哪些论文细节改变了判断

**RD-Agent-Quant 的可借鉴程度高于其宣传收益数字。** 主实验使用 2008–2014 训练、2015–2016 验证、2017–2020 测试；补充实验扩至 CSI500/NASDAQ100 的 2024–2025 年中。它提供因子单独、模型单独和联合优化对照。但补充实验使用的部分 LLM 知识截止覆盖测试前段，论文的费用叙述也有需复现时核对的不一致。附录配置是双 Xeon、4×48 GiB A6000，不能把作者整套实验时间套到单卡机器。优先复用因子单独实验，并自行冻结计算及搜索预算。[论文 §4、附录 C–D](https://arxiv.org/pdf/2505.15155)

**FinRL-DeepSeek 提供了有价值的反例。** 论文中，2019–2022 训练、2023 测试的初步结果里，LLM 改善 PPO 但仍未超过 Nasdaq；2013–2018 训练、2019–2023 测试、40 万步设置中，加入 LLM 反而变差。延长到 200 万步后又出现改善。说明结论依赖训练预算与市场状态，不能推出“加新闻或 DeepSeek 必然更好”。现代模型阅读较早历史新闻还需独立处理知识泄漏。[论文 §5](https://arxiv.org/pdf/2502.07393)

**Alpha-R1 的结果值得追踪，但可复现性尚不足。** 作者报告在 2025 上半年，CSI300/CSI1000 累计收益分别为 12.99%/42.49%，以五次运行平均呈现；使用 2024 下半年训练和交易成本/涨跌停约束。这是半年作者回测，不能视为跨周期有效性。其官方代码与权重尚未发布，是目前比收益数字更直接的准入缺口。[论文 §4](https://arxiv.org/pdf/2512.23515)、[官方待发布清单](https://github.com/FinStep-AI/Alpha-R1)

**Trade-R1 的过程奖励值得先用于评测。** 它将事实、推导、决策的一致性加入奖励，使用 Qwen3-8B 全参数 GRPO、每问题八个 rollout；测试仅 2025 年 7–10 月。论文也承认跨完整市场周期和 verifier hacking 仍待验证。语义分数、幻觉率来自其验证设计，不能当作无偏客观真值。另一个 **Trading-R1** 报告 RL 阶段使用 8×H200，其官方仓库目前也仅承诺后续 Terminal。两者均不适合作为单卡下一步直接照搬的训练工程。[Trade-R1 §4–Limitations](https://arxiv.org/pdf/2601.03948)、[Trading-R1 训练配置](https://arxiv.org/pdf/2509.11420)、[Trading-R1 仓库](https://github.com/TauricResearch/Trading-R1)

## 多 CPU + 单卡 5090 如何使用

以用户提供的硬件为规划条件；本轮没有连接服务器确认 CPU 核数、内存、驱动、空闲显存或现有模型。5090 官方规格为 32 GB 显存。[NVIDIA 规格](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5090/)

| 资源 | 第一阶段用途 | 条件与边界 |
|---|---|---|
| 多 CPU 服务器 | 行情整理、PIT 特征、线性/LightGBM、不同时间折与账户重放 | 显式分配每任务线程，防止外层并行乘以内层线程造成超额占用；先测内存/磁盘再扩并发 |
| 5090 | 小批次本地 LLM 生成候选因子、提取冻结新闻特征、嵌入；输出缓存后供 CPU 重用 | 8B 级模型是合理起点；精度、上下文和批次需实测。大模型量化“装得下”不代表吞吐合适 |
| 后续 5090 训练 | 小型 RL policy；通过前置实验后尝试小模型 LoRA/QLoRA | 单卡可行性取决于序列长度、rollout 数和优化器，不承诺原论文吞吐或完整 8B 全参数 GRPO |

8B 的 BF16 参数本身约 16 GB，这是粗略容量推算，不含梯度、优化器、激活、KV cache 或额外参考/奖励模型。标准训练占用远高于推理；CPU offload 的可运行性也不能替代性能测量。本地研究模型沿用既有“研究用途”边界，不因此次规划自动获得生产 Agent 或交易权限。

## 下一轮最小完整实验

这是独立开发研究提案；具体证券范围、日期和数据权限通过数据盘点后冻结，不能占用现有 holdout。以下计算上限是建议，不是已经启动的任务。

1. **先定任务与数据。** 若有合格横截面行情及历史成分，就做日频选股；只有现有 ETF 收盘快照时，只能做窄范围时序实验，不能称为复现 Alpha158 横截面研究。第一轮选股建议从已有权限覆盖的 OHLCV 开始，不混入历史版本不完整的财务/分析师字段。按真实可见时间冻结复权、停牌、退市和股票池。
2. **训练两个学习基线。** 同一组已验证的 Alpha158 输入分别训练线性模型与 LightGBM；数据不足则明确命名为特征子集。与既有可执行机械基准使用相同资金、约束与成交路径。先做三个不重叠开发测试窗口、每模型一个种子；只有完整可重放且显示增量才扩至预注册的三个种子。窗口是开发筛选，不是正式 alpha 证明。
3. **只改变因子研究方法。** 固定 LightGBM、标签、组合构造及执行，比较原始特征、固定预算机械/随机公式搜索、LLM 提议公式、AlphaGen 搜索。建议每搜索臂最多 20 个独立候选，每个候选最多两次实现修复；失败、重复和无效候选均计预算。无需先跑完四臂：先完成原始与 LLM 小样，方向不佳即停止扩展。LLM 只能获得训练/开发验证反馈，不能反复读取测试收益。重复尝试同一验证集的次数完整登记。
4. **再单测新闻与仓位。** 先比较价格模型与同模型加 PIT 新闻特征；若新闻没有增量，停止新闻驱动 RL。单独测试因子模型分数 + 确定性配置，对照相同信息 + 小型 PPO 配置。初始动作可限为少量目标暴露档位，但不能将本项目的 ETF 结论扩张为全市场选股。只有要研究交互效应时才补齐价格/新闻 × 固定/RL 的完整四臂；不让信息差异冒充算法差异。
5. **通过后才研究 LLM 训练。** 先使用冻结小模型做因子筛选或证据一致性评测。只有无需训练的 LLM 已产生可重复增量、训练数据权利/PIT 合格且单卡 profile 合理，才设计 SFT/LoRA 与 RL 的额外对照。训练、调参和研究搜索产生的所有成本均归因到该方案。

采用“开发筛选 → 冻结方案 → 新样本确认 → 现有正式准入”的顺序。不得根据确认样本中途挑选赢家、调整阈值或延长训练；失败后若改设计，使用新版本及新的确认样本。训练标签跨越验证/测试边界时剔除重叠；标准化、缺失填补、特征筛选和权重校准只拟合于训练侧。

评价至少覆盖：RankIC/稳定性、费用后相对收益、最大回撤、CVaR、换手、平均暴露、无法成交、加倍费用、运行/研究成本。统计按日期或事件簇处理相关性；H5 重叠标签、股票条数和多个随机种子均不能冒充独立市场样本。平均暴露更低导致的低回撤，应同时与匹配暴露的机械对照比较。短窗口尾部指标只作描述。

停止扩展的条件是：数据/PIT 不合格、无法重放、增量只来自更大资金暴露/少算成本，或开发配对没有稳定方向。若结果通过开发筛选，正式成功仍依照 [Agent Effectiveness Acceptance](AGENT_EFFECTIVENESS_ACCEPTANCE.md#balanced-acceptance-gate)，不会因本报告的三个窗口或少量因子实验而降低。

## 接入方式与交付

继续使用唯一 Harness owner。上游工具可以输出只读特征、冻结模型分数或语义明确的目标权重；Harness 注入身份、来源、截止时间和许可，现有策略/组合路径负责消费。Nautilus 和已有账户逻辑继续负责执行、资金、风险与重放。训练环境若不能忠实使用已验收的状态转移，就先作为离线方法实验，不把其回测收益写作项目账户收益。

每轮交付应包括：固定源代码/模型版本、数据与 PIT 清单、训练/验证/测试日期、所有候选及失败次数、运行与资源成本、完整账户曲线和配对差异，以及明确的“继续/停止/缺数据”结论。无需新增 UI、常驻服务、第二引擎或多 Agent 辩论框架。可信自动化闭环的工程验收继续按原 roadmap 推进，不等候发现 alpha 后才补齐。
