## 冻结目标

全球方法研究期为 2006-09-08 至 2021-09-07。方法正文、正反例及其结果依据不得来自更晚时期。最近五年 2021-09-08 至 2026-09-07 是后续连续账户对照区间，不按年重置。该区间部分结果已经打开，模型发布前训练也可能包含历史材料，因此不称为完全未知的盲测。模型权重在推理时保持冻结。

每组初始现金 CNY 200,000，无新增资金、无借款、仅做多；允许单一标的集中持仓和自主现金比例。每日收盘后研究与账户复核，最早下一交易日执行。当时已上市 A 股和 ETF 可进入发现范围，交易与估值需有历史规则和数据支持；不能用当前存续名单、当前板块规则或当前 ETF 分类替代历史事实。当前 LightGBM 预测不作为必选输入。

## 唯一主要处理

A 组不提供可选投资方法；B 组提供冻结的名称、介绍和读取位置，由模型自行选择是否读取正文及采用方法。两组保留相同基础政策、市场和账户工具、模型、采样及预算边界。方法读取是 B 组的增量能力，不增加交易权限。两组历史独立，允许共享不可变源数据，不共享答案或摘要。

保留旧运行的预加载语义。新接入使用现有 SkillRegistry 的内容/权限绑定、固定 pi 的公开 Skills 接口，以及现有 Journal 的工具回执和恢复。目录可见、正文已读、决策引用分别描述；读取不等于有效使用。研究方法不能作为当前市场事实引用。

## 接入实现与证据边界

`FrozenMethodCatalog.freeze(SkillRegistry(...))` 绑定方法内容和权限；研究、账户复核及连续账户运行时接收可选 `method_catalog`。固定版本 pi 的 `formatSkillsForPrompt` 仅生成名称、介绍和位置。正文由受限 `read` 工具返回，读取必须匹配已提供的精确路径与冻结内容哈希。目录不能读取其他实验组的账户或历史。旧入口默认不传目录，继续原有预加载语义。

目录身份、正文读取回执、研究／账户输出中的方法引用分别保存在原有工件与 Journal 中，不设第二个选择状态库。读取事实不等同于正确应用或投资有效。当前基本历史材料来自 [7 张方法卡和 13 个原始来源](research/skills-ablation-20260908/METHOD_RESEARCH.md)，覆盖十个问题方向，但正反案例和迁移验证的缺口继续保留。

历史账户增加显式 `after_close` 复核模式：使用已完成的当前交易日价格和成交量，下一交易日开盘前不引用其实际开盘价、停牌状态或涨跌停结果。当前收盘价推导的正常交易日边界只用于保守规模估算，执行仍需重新核验下一交易日源数据。历史 Backtest 的 v3 Mandate 可跨最多 14 天休市；纸面权限仍为一天，实盘边界未扩展。

MTP 前缀配置的服务器计数为 1,906 个草稿 token、1,505 个接受，接受率 78.96%。短任务未达到前缀缓存块长度，另用实际 8,631 输入 token 的合成账本核验：冷请求 3.06 秒、热请求 1.00 秒，服务器累计报告 21,600 个命中 token。早期 API 未开启用量详情，`cacheRead=0` 不代表服务器没有命中；后续启动加上 `--enable-prompt-tokens-details`，分别保留两类计数。

两个独立 pi Provider 的并发探针观察到服务器同时运行 2 个请求，双请求用时 3.28 秒；单序列配置同样两请求约 2.01 秒。此样本不支持采用批处理。FP8 KV 的短任务更慢，长输入的前三次答案正确；第四次被操作方提前停止，单列为操作中断，不算模型答错或完整并发比较。最终 QAT 候选保留 BF16 KV、MTP 2、前缀缓存和单序列。

完整工具轨迹实际触发了 64K 保守上下文边界，且一次研究耗尽 8,192 输出 token 后只有思考内容。因此业务配置扩到 96K，并预留 16K 输出；64K 的短任务成绩不代替该配置的端到端验收。Q5 96K 占用约 24,968 MiB 显存；QAT 的最终资源和业务耗时随验收回执记录。未在没有需求证据的情况下测试 128K。

原生链路试跑还暴露了 UTF-8 工具历史估算、压缩后固定任务保留、最终 JSON 外夹叙述和候选叙述标量格式问题。接入复用 pi 公开压缩／续接接口；JSON 格式最多纠正两次且受原预算约束，原始响应与纠正后的请求均留存。候选 `transmission`/`gaps` 的单段文本规范化为单项数组并记录路径；证据 ID、候选证明、权限和业务语义不由格式修正生成。历史失败记录保留，不将离线重新解析写成已完成账户。

账户初始请求曾因候选来源记录列表达到约 1.29 MB 而在派发前被预算拒绝。修复复用已有的来源追溯投影：只将候选的 `source_record_hashes` 列表改成内容哈希、数量与完整输入工件 JSON 指针，经济信息和完整验证输入保留。修复后的同一账户请求投影为 24,277 字节。新绑定显式记录投影版本；没有该标记的旧运行仍按原方式回放。真实原生请求与追溯重建测试通过。

成功的 QAT 镜像下载日志记录 29 分 11 秒；此前官方入口失败尝试另留日志，不能把成功下载时间当成全部准备时间。Q5 复用此前已校验权重，本次无需重下。vLLM 一次新配置的 graph 编译约 77 秒，不同配置的冷启动约 1–5 分钟，缓存命中后的启动时间不代表初装成本。全部权重和候选参数见 [运行时冻结清单](research/skills-ablation-20260908/runtime-manifest.json)。额外集成试跑的累计秒数、失败阶段、物理请求数和工件哈希见 [业务试跑清单](research/skills-ablation-20260908/business-trials-summary.json)，与正式 20 分钟分开。

## 用户授权的单配对补充

用户在 15:57:52 UTC 要求至少等待完成一次操作。补充实验于 16:00:27.642674 UTC 开始，只运行普通窗口的同一个研究日和下一交易日结算，A/B 各一日，完成一对即结束。两组单角色时限统一从 300 秒调整为 600 秒，其余模型、方法正文、上下文、工具和账户权限冻结。新预算与注册身份单列，不追加到原 20 分钟分子，也不据此授权多日或五年全量运行。

第一段补充 `q5-one-pair-supplement-v1` 用时 1,017.80 秒，A 组完成 494.05 秒的现金账户日；B 组 523.53 秒后未完成，仍为零配对。21 次物理请求均有最终用量。B 组压缩完成，但固定任务、摘要和近期历史重建后的请求为约 100,495 UTF-8 字节，超过 96K 配置保留 16K 输出后的保守输入上限，派发前被拒绝。此前上游文本 token 保留估算没有充分扣除固定任务和摘要空间。

用户提出上下文配置疑问后，使用原生 pi 请求转换及 llama.cpp 的 `/apply-template`、`/tokenize` 核对失败请求：实际模板为 **39,407 token**，并未接近 96K；测量耗时约 0.30 秒，无生成调用。[测量摘要](research/skills-ablation-20260908/context-tokenizer-check.json)仅公开尺寸与哈希，原始市场内容保留私有。问题是把 UTF-8 字节上界作为 token 额度，不能把 10 万字节写成 10 万 token。

## 输出必要性与实际输入视图审计（2026-09-09）

[内容与输入审计](research/skills-ablation-20260908/output-input-audit.json)将原生响应片段用同一基模的已冻结 QAT tokenizer 离线编码，无生成调用。片段合计 61,181 token，低于服务端权威输出 62,110 共 929；差额包含工具包装／分隔及独立片段编码差异，因此以下仅为近似分解，不取代账单用量：thinking 47,321（约 76%），文本 12,995（约 21%，含中途 commentary），工具参数 865（约 1%）。本轮输入 333,941、其中缓存 220,459，本来就高于输出；异常是输出长度和时间占比，并非输出数量超过缓存输入。

可直接看到的结构性开销：Q5 显式开启 thinking，研究／账户每次可输出至 16K token，单角色总输出上限 49,152，这些是上限而不是配额，但缺乏与当前信息增量相称的输出收敛要求。三个独立模型会话分别发现、研究、复核，研究 JSON 的 thesis／expectations／priced_in／counter_scenario／unknowns／candidate_comparisons 之后，账户 JSON 又展开相近的 rationale／priced_in／transmission／counter_scenario。首次研究也产出 revision 三字段；prompt 虽只在存在 prior 时要求其非空，首轮模型仍花文字解释初始基线。A 的市场排序与同一证券 lookup 在发现阶段内部就重复，B 也存在重复 lookup；跨角色的再次读取还应与其独立授权／上下文需求分开判断，不能一概删除。

真实研究输入仅有少量候选的行情、粗估值与流动性，缺少事件／财报材料，但通用事件研究格式仍容许模型大篇幅解释没有证据、假设、现金机会成本和重新入场。必要性判断应围绕证据、不同解释和风险，而非以所有文字都经过生成就认定有用。当前没有证据证明这 4.7 万 thinking token 全部必要；也没有低输出对照证明删掉其中某个比例后决策质量不变。

建议下一版本先明确每阶段需要产出的新增信息：发现仅交接短名单、简短理由及已观察事实引用；研究保留必要论据、反证和条件，修订内容只在存在旧观点时输出；账户复核聚焦持仓／风险／可执行性与行动增量，引用已完成研究而不重写。模型自行选用方法的处理保持独立，硬权限、证据、PIT、规模和执行校验继续由 Harness 负责。再在完整账户日比较思考与输出预算，而非仅把 max_tokens 截小导致截断／返工。若总输出减半且其他耗时不变，当前 19.1 分钟约变为 10.9 分钟；降至 20K 输出约 8.0 分钟。都是条件情景，尚未获得质量保持与加速验收，未修改生产实现或冻结配置。
